# Журнал архитектурных и проектных решений

## 1. Назначение документа

В этом файле фиксируются согласованные решения по архитектуре, математической модели, технологиям и организации разработки.

При изменении решения необходимо указать причину, последствия и дату. Если решение отменено или заменено, его история сохраняется.

## 2. Принятые решения

### D001. Язык программирования

**Решение:** Python 3.13.

**Причина:** язык используется для разработки расчётной модели, оптимизационного алгоритма, тестов и веб-интерфейса.

### D002. Основные библиотеки

**Решение:** NumPy, Pandas, Matplotlib, pymoo, Flask и pytest.

**Назначение:**
- NumPy — численные расчёты;
- Pandas — обработка табличных данных;
- Matplotlib — визуализация;
- pymoo — многокритериальная оптимизация и NSGA-II;
- Flask — веб-интерфейс;
- pytest — автоматические тесты.

### D003. Расчётная модель остойчивости

**Решение:** реализовать собственную упрощённую модель на NumPy.

**Причина:** расчётная логика должна быть прозрачной, тестируемой и адаптируемой к доступным исходным данным судна.

**Ограничение:** модель не должна выдавать результаты, требующие отсутствующих гидростатических характеристик. Принятые допущения и границы применимости необходимо документировать.

### D004. Оптимизационный алгоритм

**Решение:** использовать pymoo и алгоритм NSGA-II для многокритериальной оптимизации.

**Предварительное представление решения:** особь задаёт перестановку контейнеров, а декодер преобразует её в план размещения.

**Уточнение:** формат кодирования, правила декодирования и состав критериев окончательно фиксируются после формализации математической модели.

### D005. Последовательность портов

**Решение:** в базовом сценарии используется последовательность Калининград → Санкт-Петербург → Мурманск.

**Требование:** порядок портов задаётся конфигурацией и не должен быть жёстко прописан в алгоритмах.

### D006. Типы контейнеров

**Решение:** сухие, рефрижераторные и танк-контейнеры представлены типами или настраиваемыми характеристиками.

В первой версии тип контейнера сам по себе не меняет физическую модель размещения. Возможность учитывать специальные ограничения должна добавляться отдельно.

### D007. Идентификаторы контейнеров

**Решение:** идентификаторы контейнеров должны быть уникальными в наборе данных и могут принимать значение `0`.

**Требование:** идентификатор `0` не считается ошибочным только из-за своего значения.

### D008. Конфигурация проекта

**Решение:** параметры судна, ограничения, последовательность портов и сценарии хранятся в конфигурационных файлах JSON.

**Требование:** алгоритмы не должны зависеть от одной заранее заданной размерности грузовой сетки или единственного сценария.

### D009. Архитектурное разделение

**Решение:** вычислительная логика отделяется от веб-интерфейса.

Предполагаемые уровни:
- доменные сущности и модель данных;
- расчёты и алгоритмы оптимизации;
- сервисный слой;
- хранилище данных;
- пользовательский интерфейс на Flask.

Ядро проекта не должно зависеть от Flask.

### D010. Тестирование

**Решение:** использовать pytest.

Для расчётной модели, ограничений, декодера и алгоритмов необходимы автоматические тесты. Для критичных вычислений предпочтительно сначала определять ожидаемое поведение, затем реализовывать код.

### D011. Допущение о танк-контейнерах

**Решение:** в первой версии не моделируется дополнительное влияние свободной поверхности жидкости на остойчивость.

**Последствие:** результаты для планов с танк-контейнерами не учитывают этот эффект. Допущение должно быть явно отражено в документации и при интерпретации результатов.

### D012. Конфигурация грузовой сетки

**Решение:** размерность грузовой сетки и доступность позиций задаются параметрами судна.

**Требование:** проект должен поддерживать разные конфигурации без переписывания основной логики.

### D013. Единицы измерения

**Решение:** для каждой физической величины должны быть явно указаны единицы измерения. Преобразования между килограммами и тоннами, метрами и другими единицами выполняются в определённых местах программы, а не неявно.

### D014. Проверка исходных данных

**Решение:** входные данные проверяются до запуска оптимизации.

Проверяются обязательные поля, допустимые значения, уникальность идентификаторов, корректность портов назначения и согласованность контейнеров с доступными позициями.

## 3. Предварительные параметры модели

Следующие значения рассматриваются как начальные проектные настройки, а не как подтверждённые нормативы для конкретного судна:

- минимальная метацентрическая высота GM: 0,15 м;
- целевое значение GM: 0,50 м;
- максимальный крен: 1°;
- ограничение дифферента: 1% длины судна;
- предварительная нагрузка на колонну: 60 т;
- предварительная нагрузка на поперечное сечение: 220 т;
- максимальная масса контейнера: 30 480 кг.

Значения должны храниться в конфигурации и проверяться по доступным техническим данным и принятой методике.
