
# PROJECT_CONTEXT.md — контекст дипломного проекта

## Назначение

**Тема:** «Разработка программного обеспечения для оптимизации размещения контейнеров на судне с учётом остойчивости и минимизации перевалок».

Дипломный проект СПбГМТУ. Планируемая защита — июнь 2027 года.

Программа должна формировать и сравнивать варианты размещения контейнеров на судне, учитывать ограничения загрузки и остойчивости и минимизировать потенциальные перевалки при последовательной выгрузке в портах.

Используется упрощённая математическая модель синтетического судна типа `box-barge`. Программа является учебным прототипом, а не сертифицированной системой проверки безопасности судна.

## Репозиторий и окружение

- GitHub: https://github.com/liklife/diploma-container-optimization
- Рабочая ветка: `migration/target-structure`
- ОС: Windows 11
- Python: 3.13.2
- Окружение: существующее `.venv`

Утверждённый стек: NumPy, Pandas, Matplotlib, pymoo (NSGA-II), Flask, SQLite и pytest.

Зависимости определяются существующими файлами проекта. Новые библиотеки без согласования не добавляются.

## Архитектура

Основной Python-пакет находится в `src/stowage/`.

| Каталог | Назначение |
|---|---|
| `domain/` | Контейнеры, судно, слоты, маршрут портов и план размещения |
| `model/` | Расчёты массы, центра тяжести, остойчивости и проверки ограничений |
| `algorithms/` | Алгоритмы размещения, декодирование и оптимизация |
| `datagen/` | Подготовка и генерация тестовых данных |
| `storage/` | Работа с SQLite |
| `services/` | Прикладная логика |
| `viz/` | Визуализация результатов |
| `web/` | Веб-интерфейс Flask |

Это целевая структура. Наличие каталога не означает, что соответствующий функционал уже реализован.

Параметры модели задаются в `configs/`, тесты находятся в `tests/`. Исторический код отделён в `legacy/`.

## Источники истины

Этот файл содержит постоянный контекст проекта, а не журнал разработки.

Актуальный статус реализации определяется по `docs/state.md` и фактическому коду. Состав, требования и состояние задач проверяются в GitHub Issues.

Не копируй сюда перечень задач, результаты тестов или временные сведения о ходе разработки.

Перед реализацией задачи используй:

1. `docs/decisions.md` — утверждённые архитектурные и проектные решения.
2. `docs/model.md` — постановка задачи и границы математической модели.
3. `docs/math_model.md` — формулы, расчётные зависимости и допущения. Приоритет имеет актуальная локальная версия.
4. `docs/state.md` — текущее состояние разработки и ближайшие этапы.
5. `configs/*.json` — параметры судна, ограничения и последовательность портов.
6. `docs/divergences.md` — известные расхождения и статус их устранения.

Дополнительно:

- `README.md` — обзор и инструкции по запуску.
- `PROGRESS.md` — история выполненной работы.
- GitHub Issues — состав и критерии выполнения задач.

Не используй этот файл вместо первичных документов. Если сведения расходятся, сообщи пользователю и запроси решение.

## Организация разработки

Разработка ведётся небольшими согласованными задачами. ChatGPT помогает планировать и проверять решения, Codex реализует утверждённые изменения, пользователь контролирует результат через VS Code и Git.

Перед любыми изменениями Codex обязан соблюдать `AGENTS.md`.
